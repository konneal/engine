# F3 — Exhaustiveness and provable absence

**Powering objects:** the CLOSED WORLD — aspects.yaml's audit line
("audit of all 60 requirements + 62 tests"), requirements/ and
conformance/ as enumerated registries, forAll semantics in constraints.

**The win — two directions:**
1. **Complete listing:** *"list EVERY requirement that binds the
   load cell's markings"* → the aspects registry (markings ← R 60-1
   6.2.1/6.2.4, examined by /conf/examinations/inscriptions…). The
   answer is EXHAUSTIVE by construction, with the audit count as
   metadata. Retrieval lanes return a top-k subset and cannot promise
   completeness.
2. **Provable NO:** *"does R 60 constrain the load cell's packaging
   for shipping?"* → no requirement, no aspect, no test binds
   "packaging" → the answer is NO with the enumeration as proof. A
   document lane must refuse ("not found") — absence of evidence.
   The model lane PROVES absence of the requirement.

**Why it matters:** "no" answers are the scariest in conformity
assessment; provable absence turns them into the safest.
